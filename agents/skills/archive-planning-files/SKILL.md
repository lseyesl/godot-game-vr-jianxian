# Archive Planning Files

将项目根目录下的规划文件（`task_plan.md`、`findings.md`、`progress.md`）归档到 `docs/archive/` 目录。

## 触发条件

用户说出以下任意触发词时激活此 skill：
- "归档"
- "archive"
- "清理规划文件"
- "存档"

## 前置检查

归档前 **必须** 依次执行以下验证：

### 1. 文件存在性检查

检查项目根目录下是否存在以下文件：
- `task_plan.md`
- `findings.md`
- `progress.md`

**如果三个文件都不存在**：告知用户没有可归档的规划文件，停止执行。

**如果部分文件存在**：列出缺失的文件，询问用户是否仍要归档已有的文件。仅当用户确认后才继续。

### 2. 完成状态确认

读取所有存在的规划文件，逐一检查完成状态：

| 文件 | 完成判定规则 |
|------|-------------|
| `task_plan.md` | 所有阶段（phase/stage）状态均为 `complete` / `✅` / `已完成`，不存在 `in_progress` / `pending` / `TODO` 状态的阶段 |
| `progress.md` | 最后一条记录表明任务已结束（包含 "完成"、"done"、"completed"、"closed" 等关键词），或没有未解决的错误 |
| `findings.md` | 无阻塞状态（没有标记为 `blocked` / `unresolved` / `未解决` 的条目） |

**如果任一文件未完成**：
1. 明确告知用户哪些文件未完成，以及具体的未完成项
2. **停止执行**，等待用户决定：继续归档还是先完成未完成的工作
3. 仅当用户明确说"强制归档"或"仍然归档"后才继续

## 归档执行

### 1. 生成摘要

读取所有存在的规划文件，生成一份结构化摘要，包含以下部分：

```markdown
# 归档摘要

> 归档时间: YYYY-MM-DD HH:mm:ss

## 目标
[从 task_plan.md 提取的核心目标，1-3 句话]

## 完成阶段
[从 task_plan.md 提取各阶段及完成状态]

## 关键发现
[从 findings.md 提取最重要的 3-5 条发现]

## 过程记录
[从 progress.md 提取关键节点：开始时间、重大决策、遇到的错误及解决方案、完成时间]

## 文件清单
[列出本次归档涉及的源文件及其最终状态]
```

### 2. 确定 slug

从 `task_plan.md` 的目标或标题中提取 2-4 个关键词，用连字符连接，全小写，作为 slug。
如果 `task_plan.md` 不存在，从 `progress.md` 的内容推断 slug。

示例：
- 目标为"实现飞剑拖尾特效" → slug: `sword-trail-effect`
- 目标为"Add height limit enforcement" → slug: `height-limit-enforcement`

### 3. 保存归档文件

- 目标目录: `docs/archive/`（如果目录不存在，先创建）
- 文件名格式: `YYYY-MM-DD_HH-mm-ss-{slug}.md`
- 时间戳使用当前本地时间
- 文件内容: 步骤 1 生成的结构化摘要

### 4. 删除源文件

归档文件写入成功后，删除项目根目录下已归档的源文件：
- 删除 `task_plan.md`
- 删除 `findings.md`
- 删除 `progress.md`

**仅删除本次实际归档的文件**。如果某个文件在步骤 1 中不存在，跳过删除。

### 5. 确认归档

向用户报告归档结果：
- 归档文件路径
- 摘要概览（目标、阶段数、关键发现数）
- 已删除的源文件列表

## 边界情况

| 情况 | 处理方式 |
|------|---------|
| 三个文件都不存在 | 告知用户，停止 |
| 部分文件不存在 | 列出缺失文件，询问是否继续 |
| 文件存在但为空 | 视为已完成，正常归档（摘要中标注"文件为空"） |
| 用户强制归档未完成的文件 | 在摘要中明确标注未完成项，正常保存和删除 |
| `docs/archive/` 不存在 | 创建目录后继续 |
| slug 冲突（同名文件已存在） | 时间戳确保唯一性，不会冲突 |
